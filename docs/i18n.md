# Internationalisation

Netcross traduit son interface avec **GNU gettext** (issue #299). La langue
source est le **français** : les chaînes sont écrites en français dans le
code, les catalogues `lang/<locale>.po` en donnent les traductions.

## Arborescence

```text
lang/
├── LINGUAS        # la seule liste des langues (29 au départ)
├── messages.pot   # modèle, généré depuis les sources
├── ar.po … zh.po  # un catalogue par langue de LINGUAS
scripts/
├── i18n-update.sh # xgettext → msgmerge → msgfmt
└── i18n_report.py # état des traductions (texte, Markdown, JSON)
src/netcross_core/i18n.py   # _(), ngettext(), N_(), setup()
```

Les `.mo` compilés ne sont pas versionnés : ils sont produits par
`scripts/i18n-update.sh --compile` (par défaut dans
`src/netcross_core/locale/`, ignoré par git) et par le packaging, qui installe
toutes les locales de `LINGUAS` dans
`/usr/share/locale/<locale>/LC_MESSAGES/netcross.mo`.

## Marquer une chaîne

```python
from netcross_core.i18n import N_, _, ngettext

status = _("Analyse terminee.")
message = ngettext(
    "Comparaison terminee -- {n} regression detectee.",
    "Comparaison terminee -- {n} regressions detectees.",
    count,
).format(n=count)

# constante de module : évaluée avant le choix de la langue
LABEL = N_("Paquets")  # extraction seule
text = _(LABEL)  # traduction à l'affichage
```

- Pas de f-string dans `_()` : `xgettext` ne verrait pas la chaîne finale.
  Utiliser des champs nommés `{n}` et `.format()` ; les tests vérifient que
  chaque traduction conserve exactement les mêmes champs.
- Toujours `ngettext` pour un nombre : les règles de pluriel varient (une
  forme en japonais, trois en russe, six en arabe).
- Une note pour les traducteurs se place en commentaire
  `# Traducteurs : ...` juste au-dessus de l'appel.

## Choisir la langue

`NETCROSS_LANG=en netcross-gui` ; sinon les variables standard `LANGUAGE`,
`LC_ALL`, `LC_MESSAGES`, `LANG`. `NETCROSS_LANG` accepte une liste de repli
(`pt_BR:pt:en`). Sans catalogue, l'interface reste en français.
`NETCROSS_LOCALEDIR` désigne un répertoire de catalogues compilés prioritaire.

## Mettre à jour les catalogues

```bash
sudo apt-get install gettext
scripts/i18n-update.sh              # .pot + msgmerge de tous les .po + msgfmt --check
scripts/i18n-update.sh --check      # vérifie sans écrire (CI)
scripts/i18n-update.sh --compile    # .mo dans src/netcross_core/locale/
python3 scripts/i18n_report.py      # état par langue
```

`msgmerge` conserve les traductions existantes ; une chaîne modifiée devient
`fuzzy` (avec l'ancienne version en `#|`) et une nouvelle arrive avec
`msgstr ""`. Aucune traduction automatique n'est insérée : une proposition
automatique éventuelle doit rester marquée `fuzzy` jusqu'à relecture.

## Ajouter une langue

1. ajouter son code dans `lang/LINGUAS` ;
2. lancer `scripts/i18n-update.sh`, qui crée `lang/<code>.po` (si `msginit`
   ne connaît pas ses pluriels, il le signale : compléter l'en-tête
   `Plural-Forms`) ;
3. traduire les `msgstr` ;
4. ouvrir la PR : la CI vérifie et compile.

Aucun code n'est à modifier : ni l'application ni le packaging ne contiennent
de liste de langues (un test l'interdit).

## Intégration continue

Le workflow `i18n.yml` :

- sur chaque PR touchant les sources ou `lang/` : échoue si `messages.pot`
  ou un `.po` n'est plus synchronisé avec le code, si un catalogue est
  invalide (syntaxe, pluriels, formats) ou ne compile pas, et publie le
  résumé (langues, messages, traduits, non traduits, fuzzy, chaînes
  nouvelles et supprimées, locales compilées) ;
- sur `dev` (et à la demande) : régénère les catalogues et ouvre ou actualise
  la PR `chore(i18n): update translation catalogs`, limitée à `lang/`. Une PR
  ouverte par le jeton du workflow ne relance pas la CI : la relancer
  manuellement avant fusion.

`tests/test_i18n.py` vérifie aussi, sans gettext : synchronisation `.po` /
`.pot`, en-têtes `Language` et `Plural-Forms`, champs `{…}` conservés,
références vers des fichiers existants, absence de liste de langues dans
`src/`, et que les modules déjà convertis n'ont plus de chaîne utilisateur
non marquée (`GETTEXT_MODULES`).
